## サイト内容の恒久ルール
- 掲載する商品は**3本＋リンク2本で確定済み**(archive/phase2-instructions.md §0-11)。SAS対策プログラムと勤務設計レビューは実績ができるまでトップに掲げない
- 健康経営について書く際は、**認定要件と調査票を混同しない**(同 §0-11b)。令和8年度の変更は「案」の段階のため「新設される方針が示されています」と表現する
- 「睡眠専門医」という語の使用禁止(肩書きは 内科専門医・心療内科専門医・労働衛生コンサルタント の統一表記のみ)
- 確定文言(`docs/copy/` 配下)の改変禁止 — 改善案がある場合は実装せず「提案」として報告する

## 進め方
- 1タスク = 1コミット。コミットメッセージは「T2B: 問い合わせフォーム新設」の形式
- 各タスク完了時に、変更内容の要約・確認手順・スクリーンショット(取得可能な場合)を報告し、**承認を得てから次のタスクに進む**(勝手に先へ進まない)
- 破壊的操作・公開に関わる操作は、実行前に必ず明示承認を得る

## 絶対禁止
- **明示承認のない `main` へのpush**(両Azure Static Web Appsがデプロイされるため。毎回差分提示→承認)
- 親テーマ・プラグイン本体・WordPressコアの直接編集(カスタマイズはすべて子テーマ内)
- 指示のないプラグイン追加/既存ページ・記事・画像の削除
- **無承認でのDNS変更**。DNS変更は毎回「変更前後の差分一覧を提示→承認→XServer API経由で適用」の順を厳守。Azure SWAのカスタムドメインを支えるレコードには一切触れない
- サーバーパネル・レジストラのログイン情報の受領、ブラウザ自動操作によるログイン試行
- APIキー・接続文字列・パスワード類のコミット・画面表示・ログ出力(`.env`(gitignore済み)のみで扱い、在り処だけREADMEに記載)

## 安全網
- 破壊的変更の前に必ずバックアップ(DB+ファイル一式)を取得し、保存先を報告(実行時バックアップは `backups/` に生成される。過去分は `archive/2026-07-site-work/backups/`)
- 迷ったら止まって質問する。推測で進めない
- 問い合わせ動線(`/contact/`)に関わる変更は、検証チェックリスト(archive/phase1-instructions.md T6)を全項目通過するまで「完了」と報告しない
- XServer APIの操作対象は `kdkconslt-sngyouijm.com` と当該サーバーアカウントに限定。他ドメイン・他サイト・契約/支払い情報には触れない
