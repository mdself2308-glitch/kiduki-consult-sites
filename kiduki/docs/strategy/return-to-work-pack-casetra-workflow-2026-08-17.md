作成: 2026-08-17

更新: 2026-08-17 Casetra実装照合

料金正本: `../pricing-growth-canonical.md`

既存ストーリー: `../integrated-story.md`

## 1. 結論と商品境界

- 復職支援Packは150,000円／社員1名・1休職エピソード（税別）
- KIDUKIが依頼企業、担当者、対象社員、復職CaseをCasetraへ登録する
- 企業担当者はCasetraの企業画面で、Pack対象Caseの復職ToDo、期限、意見書受領、会社決裁、再評価を処理する
- Packの契約だけでCasetra月額契約にはならず、外部Casetra ARR・契約社数にも含めない
- Pack完了後に企業が自社運用を選んだ場合だけ、Casetra STARTER以上を別契約する
- Pack Caseは `PACK_INCLUDED`、通常の月額Caseは `CLIENT_BILLABLE` として実装し、Case件数と紐づく予約件数の月額カウントからPackを除外する

### 実装した商品境界

- OPS画面から企業、企業担当者、従業員を登録し、企業担当者のEntraアカウントを招待・有効化・無効化できる
- Pack担当者の署名付きセッションへ対象Case IDと期限を持たせ、企業画面には割り当てた1 Caseだけを表示する
- ポータル経路とAPIの両方で、割当て外Case、月額請求、全社機能へのアクセスを拒否する
- 操作期限後は自動的に `READ_ONLY` とし、入力済み内容と証跡の閲覧だけを残す。OPSは1画面で再開・読取専用・停止を切り替えられる
- `RETURN_TO_WORK__STD` に、起票根拠、予約確定、事前資料提出、面談実施、医師意見書、意見書受領確認、会社決裁のToDoがある
- 面談実施と医師意見書は産業医・産業保健職が編集し、企業担当者は進捗と受領物を確認する
- 会社決裁は企業担当者が、決裁状態、結論、措置、実施開始・終了、見直し時期等を入力する
- 会社決裁時にM3・M6等のフォローCaseを作成でき、Decision Packの生成処理がある
- 意見書の受領確認や会社決裁等が不足したままCaseを閉じないための完了条件がある
- 主治医照会 `TK-MI-01` を標準・外部産業医の復職フローへ追加し、会社が確認する要否・目的と、KIDUKIが処理する本人同意・送付・回答・調整履歴をフィールド権限で分ける
- Todoの完了者・完了日時・入力差分を既存の監査・Evidence chainへ残す
- Pack対象Caseとそれに紐づく予約は月額利用件数へ算入しない

### main反映後に実機で確認すること

- 実在のテスト企業担当者がOIDCで再ログインし、割当て1 CaseだけをPC・スマートフォンで閲覧できること
- 操作期限後に同じCaseが読取専用となり、更新APIも拒否されること
- Pack Caseと紐づく予約が請求プレビューへ入らないこと
- 月額相談CTAからKIDUKI問い合わせフォームへ到達すること

## 2. 役割

| 主体 | 行うこと | 行わないこと |
|---|---|---|
| 企業担当者 | 窓口設定、資料提出、予約確認、意見書受領、会社決裁、措置実施、勤務実績共有、再評価時の決定 | 医学評価を行わない。会社の決定と実施をKIDUKIへ委ねない |
| KIDUKI | 企業・Case登録、情報整理、本人同意の確認、必要時の主治医照会、日程調整、面談、産業医意見、期限管理、再評価、Decision Pack | 会社の人事決定を代行しない。診断・治療を行わない |
| 本人 | 同意、必要情報の提出、面談、生活リズム評価への参加 | 会社決裁を行わない |
| 主治医 | 診断・治療、本人同意の範囲での医学的見解 | 会社の最終就業判断を行わない |
| Casetra | ToDo、期限、編集権限、意見書受領、会社決裁、実施、再評価、証跡を一つのCaseでつなぐ | 医学判断・会社決定を自動化しない |

## 3. 15万円で進む標準ワークフロー

| 工程 | Casetraの実ToDo・表示 | KIDUKI | 企業担当者 | 完了条件 |
|---|---|---|---|---|
| 1. 企業登録・起票 | `起票根拠（TK-TR-01）`、復職Case、予定日、次のToDo | 企業、担当者、社員、Case、期限、役割を設定 | 窓口、依頼理由、復職希望時期を確認 | 企業担当者が企業画面へアクセスでき、対象Caseを確認できる |
| 2. 資料と職務の整理 | `事前資料提出（TK-IN-01）`、不足情報、期限 | 診断書、職務、休職前経過、社内制度を点検し、不足情報を整理 | 診断書、職務、会社が実施できる勤務条件を提出 | 面談に必要な医学情報と職務情報の所在が明確 |
| 3. 調整・予約・主治医照会 | `面談/会議/フォローの予約確定（TK-SC-01）`、`主治医照会（TK-MI-01）` | 日程と資料締切を調整。必要時は本人同意、照会文面、送付、回答受領、差戻しを記録 | 日程、照会要否・目的、主治医へ渡す職務情報を確認 | 面談日と資料締切が確定し、照会なし、または同意・送付・回答の証跡が揃う |
| 4. 復職前評価 | `面談実施（TK-IV-01）`。会社は進捗を確認し、編集は医師・産業保健職 | 面談し、勤務準備性、安全性、必要な就業配慮を評価 | 追加確認への回答以外は待つ | 面談記録と評価が完了 |
| 5. 医師意見の受領 | `医師出力（TK-DO-01）`、`意見書受領確認（TK-ACK-01）` | 就業可否だけでなく、勤務時間、業務制限、見直し時期等を具体化 | 意見書を受領確認し、社内決裁へ回す | 医師意見が提出され、企業側で受領確認される |
| 6. 会社決裁・実施 | `会社決裁（TK-GT-01）` | 意見の読み方と選択肢を説明するが、会社に代わって確定しない | 復職日、就業区分、残業・時短・業務・運転等の措置、実施期間、見直し時期を決定し、職場で実施 | 決裁者、結論、措置、開始時期、見直し時期が記録される |
| 7. 再評価・完了 | M3/M6等のFollow-up、未完了ToDo、Decision Pack | 勤務実績と体調を再評価し、証跡と次回予定を整理 | 勤務実績を共有し、措置の継続・変更・解除を決定 | 必須ToDoと証跡が揃い、Decision Packと次回対応を返却できる |

主治医照会は独立Todoで扱う。企業担当者は照会要否・目的・会社確認だけを入力し、本人同意、送付日時、照会文書、回答受領日時、回答証跡、調整履歴はKIDUKIが入力する。企業ロールからKIDUKI処理欄の変更とTodo完了はAPIでも拒否する。

## 4. 企業担当者が行う五つのこと

1. 窓口を決め、CasetraでPack対象の復職Caseと起票内容を確認する
2. 診断書、職務、休職前経過、会社が実施できる勤務条件を提出する
3. 面談日を確認し、必要時は主治医照会に使う職務情報と照会内容を確認する
4. 産業医意見を受領し、会社決裁画面で復職日、措置、実施期間、見直し時期を確定する
5. 決めた措置を職場で実施し、再評価時に勤務実績と継続・変更・解除を入力する

「ファイル共有1回と数クリックだけ」とは断定しない。会社決裁画面には、就業区分、残業、時短、業務量、配置、危険作業、運転、在宅、上司・人事フォロー、実施期間、見直し時期等の具体入力がある。負担を軽くする価値は、会社の責任を省くことではなく、**会社が決める項目と順番を画面に出し、KIDUKIがその前後を整えること**に置く。

## 5. 権限と情報境界

### 実装済みの境界

- 企業画面は認証された `companyId` でCaseを取得する
- `TK-IV-01` は産業医・産業保健職、`TK-DO-01` は産業医だけが編集できる
- `TK-GT-01` は企業人事が編集し、KIDUKIが会社決裁を代行しない役割分離になっている
- 会社には就業上必要な意見と進捗を返し、診療録そのものを会社決裁画面へ入力しない
- 必要な意見書受領、決裁、面談・医師意見等が不足するCaseは完了させない制御がある
- Pack担当者は署名済みセッションの `companyCaseIds` にある1 Caseだけを開け、APIにも同じスコープを信頼ヘッダーで渡す
- 期限切れは認証時に `READ_ONLY` へ変換し、ポータルとAPIの双方で更新を拒否する。OPSは `DISABLED` も選べる
- Pack企業ナビから請求と全社機能を外し、プロキシでも許可したCase取得・Todo更新以外を拒否する
- 主治医照会は会社入力欄とKIDUKI処理欄を分離し、証跡必須条件を定義する
- Pack Caseと紐づく予約を月額カウントから除外し、二重計上を防ぐ
- 月額相談CTAは問い合わせへ接続し、契約成立後は通常のオンボーディングで権限と請求を切り替える。Pack Case自体は履歴として `PACK_INCLUDED` のまま保持する

## 6. 完了後の三経路

| 選択 | Casetra | KIDUKI |
|---|---|---|
| 自社運用 | STARTER以上を別契約し、月額利用へ移行 | 必要な専門業務だけ依頼可能 |
| KIDUKI継続 | Casetraが必要なら別契約 | BasicまたはRetainへ移行 |
| 自社管理へ返却 | 月額契約なし。契約に従い出力・終了 | Decision Packと次回予定を返却して終了 |

## 7. 公開・販売前の実機受入

### main反映後に実環境で確認する項目

- [ ] 企業・担当者・従業員を登録し、企業担当者を招待できる
- [ ] 企業担当者が `TK-TR-01`、`TK-IN-01`、`TK-SC-01`、`TK-ACK-01`、`TK-GT-01` を処理できる
- [ ] 企業担当者が `TK-IV-01`、`TK-DO-01` を編集できない
- [ ] 医師意見の提出と受領確認前に会社決裁へ進めない
- [ ] 会社決裁で決裁者、結論、措置、実施開始・終了、見直し時期を記録できる
- [ ] 会社決裁からM3/M6等のFollow-upが作成される
- [ ] 必須ToDo・面談・医師意見・会社決裁・受領確認が不足するCaseを閉じられない
- [ ] Decision Packを生成し、企業へ返せる
- [ ] 他社のCaseへアクセスできない
- [ ] Pack担当者には割り当てた1 Caseだけを表示する
- [ ] Pack終了後に読取専用へ変更し、更新APIが拒否される
- [ ] 主治医照会を専用ToDoまたはEvidenceとして、本人同意・企業確認・送付・回答まで追跡する
- [ ] Pack用Caseと予約を請求・利用件数・ARRから除外する
- [ ] 月額相談CTAがKIDUKI問い合わせフォームへ到達する
- [ ] Pack用アクセスで同一企業の別社員、請求、全社名簿、月額専用機能へ到達できないことを試験する
